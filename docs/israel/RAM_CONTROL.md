# Complex systems — Ram-Control

## Stance (session)

- **Ram-Control** / Ramdor world = entrenched construction / ops systems.
- DocFlow does **not** compete with **Top Ramdor**.
- Strategy: **feed them** — become a trusted upstream of clean, routed documents and fields.

## Technical posture

- Prefer **read-only SQL views** (or equivalent read APIs) into Ram-Control data where needed for context.
- Write path is careful and late; never pitch “we replace Ramdor screens.”

## Commercial wedge inside that world

- **Subcontractor / multi-prime** pain: one sub feeds many primes, each with different document expectations.
- DocFlow angle: one field capture → many routed office packs — without asking Ramdor to change.

## Live-room language

> We integrate beside Ram-Control. We don’t rip it out. We make the documents that should already be in those views arrive clean and on time.
